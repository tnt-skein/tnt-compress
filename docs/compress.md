# Сжатие

```lua
local packed = compress.deflate(body)                     -- gzip, уровень 6
local text, err = compress.inflate(packed)                -- отказ парой, предел 16 МБ
middleware.configure({ layers = { compress = compress.layer } })
```

## Зачем пакет

Что из сжатия Tarantool 3.8 CE умеет сам, сверено запуском:

- **разжать ответ по HTTP** — умеет: `http.client` с опцией `accept_encoding`
  просит сжатие и разжимает тело сам (это libcurl), а клиент
  [tnt-http](https://github.com/tnt-skein/tnt-http) ставит её
  по умолчанию — `gzip, deflate`;
- **сжать строку** — нечем: модуль `compress` и сжатие полей кортежа есть
  только в Enterprise, zstd, которым vinyl сжимает страницы, наружу
  не выведен, а в манифесте `rocks.tarantool.org` (19.09.2026) нет ни
  одного рока сжатия.

Сжимает системная zlib, а `tnt-compress` — фасад **поверх** неё через FFI.
Она есть на любом узле, но добывается по-разному: сборка Homebrew на macOS
тянет её за libcurl, а официальный образ `tarantool/tarantool:3.8` собран
статически — символов zlib в нём нет, `ffi.load('z')` не находит
`libz.so` (это имя ставит пакет разработчика), и находит только
`libz.so.1`, который лежит в любой поставке Linux. Пакет ищет по обоим
именам.

Поверх zlib пакет даёт три вещи, которых у неё нет:

1. **Отказ парой с родом у разжатия** — `corrupt`, `truncated`,
   `too_large`, `failed` — и предел разжатого по умолчанию: килобайт
   злого входа разжимается в гигабайт.
2. **Уступки между кусками работы.** Сжатие — счёт в потоке событий,
   и сотня мегабайт без уступок держала бы узел секунду.
3. **Слой `compress`** для роутера: gzip по `Accept-Encoding`, `Vary`,
   слабая метка у сжимаемого вида, ответ по кускам, который остаётся
   потоком.

Зависит от [tnt-must](https://github.com/tnt-skein/tnt-must) (проверки
аргументов) и [tnt-external](https://github.com/tnt-skein/tnt-external)
(внешние зависимости и их подмена в проверках). Слой ставится на вход
роутера [tnt-router](https://github.com/tnt-skein/tnt-router) либо именем
в реестр [tnt-middleware](https://github.com/tnt-skein/tnt-middleware),
но ни тот, ни другой пакету не нужен: слой берёт запрос и ответ таблицами
по договору роутера и сам их не требует.

## Как пользоваться

```lua
local compress = require('tnt.compress')

local packed = compress.deflate(string.rep('узел жив\n', 1000))
#packed                                            --> 84
compress.inflate(packed) == string.rep('узел жив\n', 1000)   --> true

local text, err = compress.inflate('не gzip')
--> nil, сжатые данные испорчены: incorrect header check
err.kind == compress.CORRUPT                       --> true

compress.deflate(body, { format = 'zlib', level = 9 })
compress.inflate(upload, { limit = 1024 * 1024 })  -- предел разжатого, байт

middleware.configure({ layers = { compress = compress.layer } })
```

### Что умеет фасад

| Вызов | Что отдаёт |
|---|---|
| `deflate(data, opts)` | сжатую строку; `opts`: `format`, `level` |
| `inflate(data, opts)` | разжатую строку либо `nil, err`; `opts`: `format`, `limit` |
| `deflater(opts)` | поток сжатия: `write`, `flush`, `finish` |
| `inflater(opts)` | поток разжатия: `write`, `finish` |
| `layer(opts)` | слой ответа; он же фабрика для реестра `tnt-middleware` |
| `available()` | `true` либо `false, почему` — есть ли zlib на узле |
| `FORMATS` | `{ 'gzip', 'zlib', 'raw' }` |
| `LEVEL`, `LIMIT`, `MIN_SIZE` | 6; 16 МБ; 1024 байта |
| `CORRUPT`, `TRUNCATED`, `TOO_LARGE`, `FAILED` | роды отказа |

## Форматы

Все три — обёртки вокруг одного и того же DEFLATE (RFC 1951):

| `format` | Что это | Где берут |
|---|---|---|
| `gzip` (по умолчанию) | RFC 1952: заголовок `1f 8b`, CRC-32 и длина в хвосте | файлы `.gz`, `Content-Encoding: gzip` |
| `zlib` | RFC 1950: два байта заголовка, Adler-32 в хвосте | то, что HTTP называет `deflate` |
| `raw` | DEFLATE без обёртки | zip, `permessage-deflate` у WebSocket |

Уровень — `level` zlib, 0…9, по умолчанию 6: на строках выгрузки журнала
он сжимает почти как девятый (13,9 % против 13,8 %) втрое быстрее его.
Нулевой — хранение без сжатия, выход длиннее входа.

```lua
compress.deflate('a'):byte(1, 2)                         --> 31 139
compress.deflate('a', { format = 'zlib' }):byte(1)       --> 120
compress.inflate(compress.deflate('a', { format = 'raw' }), { format = 'raw' })   --> a
```

## Разжатие: отказ и предел

Разжимают чужое — тело запроса, файл копии, выгрузку, пришедшую по сети, —
и испорченное там «так бывает». Отказ — пара `nil, err`, где `err` —
таблица с родом и текстом; строкой, в склейке и в `json.encode` она — свой
текст.

| Род | Когда |
|---|---|
| `corrupt` | не сжатые данные, чужой формат, несошедшаяся сумма, лишние байты после конца потока |
| `truncated` | вход кончился раньше конца потока, в том числе пустой вход |
| `too_large` | разжатое больше предела |
| `failed` | zlib отказала сама: не хватило памяти |

```lua
local packed = compress.deflate(string.rep('x', 100))

compress.inflate(packed:sub(1, -2))
--> nil, сжатые данные оборваны: вход кончился раньше конца потока
compress.inflate(packed, { limit = 99 })
--> nil, разжатое больше предела в 99 байт
compress.inflate(compress.deflate('a', { format = 'zlib' }) .. 'x', { format = 'zlib' })
--> nil, сжатые данные испорчены: лишние байты после конца потока
```

**Предел есть всегда**: без `limit` — `compress.LIMIT`, 16 МБ. Больше —
называется явно. Предел считает разжатое, а не сжатое: 16 МБ нулей
сжимаются в 16 КБ, и предел по входу пропустил бы их не глядя.

**gzip разжимается членами подряд**, как у `gzip -d`: файл, в который
дописывали сжатые куски (`cat a.gz b.gz`), читается целиком. На этом
стоит выгрузка, которую дописывают партиями:

```lua
local fs = require('tnt.fs')

fs.append(path, compress.deflate(batch_one))       -- каждая партия — свой член
fs.append(path, compress.deflate(batch_two))

compress.inflate(fs.read(path))                    --> batch_one .. batch_two
-- и то же читает `gzip -dc`
```

У `zlib` и `raw` байты после конца потока — отказ `corrupt`: у них членов
нет, и лишнее означает, что вход склеен не тем, чем думали.

## Поток: `deflater`, `inflater`

Для того, чего нет целиком: копия, которая читается кусками, ответ
по кускам, тело, приходящее частями.

```lua
local deflater = compress.deflater()
local parts = {
    deflater:write('первая часть, '),          -- 10 байт: заголовок gzip
    deflater:write('вторая часть, '),          -- пусто: zlib копит вход до блока
    deflater:flush('сразу читаемое, '),         -- сброс: всё к этому мигу
    deflater:finish('последняя.'),              -- конец потока
}

local inflater = compress.inflater({ limit = 1024 })
inflater:write(table.concat(parts))
--> первая часть, вторая часть, сразу читаемое, последняя.
inflater:finish()                              --> true
```

`flush` — `Z_SYNC_FLUSH`: выход выравнивается на байт, и та сторона
разожмёт всё, что пришло, не дожидаясь конца. Словарь при этом остаётся:
повтор после сброса по-прежнему сжимается ссылкой назад. Каждый сброс
стоит несколько байт и немного сжатия.

У `inflater` предел считает разжатое **всех кусков вместе**. Отказ
липкий: после него каждый следующий `write` и `finish` отдают тот же отказ.
`finish` сверяет, что поток дошёл до конца: недописанный — `truncated`.
Кусок после `finish` — бросок.

Поток — одному файберу: работа уступает между вызовами zlib, и два
файбера, пишущие в один поток, перемешали бы куски.

## Слой `compress`

```lua
local middleware = require('tnt.middleware')

middleware.configure({ layers = { compress = compress.layer } })
-- { 'compress' }, { 'compress', { level = 4, min_size = 512 } }

router.new({ entry = { compress.layer() } })       -- или без реестра
```

Ставится на входе роутера: так сжимается всё, чем он отвечает, — ответы
API, раздача файлов и ответ по кускам. Сжимается ответ, у которого:

- тело — строка не короче `min_size` (по умолчанию 1024 байта) либо поток
  `router.stream`;
- тип — текст: `text/*`, `application/json`, `application/javascript`,
  `application/xml`, `application/x-ndjson`, `…+json`, `…+xml`;
- своего `content-encoding` и `cache-control: no-transform` нет.

Картинки, архивы и `application/octet-stream` не сжимаются: они либо сжаты
уже, либо неизвестно что. Короткое тело — тоже: обёртка gzip стоит
18 байт, а ответ до килобайта уходит одним пакетом и так.

Ответу сжимаемого типа слой ставит `vary: Accept-Encoding` **всегда** —
и короткому, и ответу без тела (304, ответ на `HEAD`), и тогда, когда
клиент сжатия не просил: у адреса два вида, и кэш по дороге, не знающий
этого, отдал бы сжатый клиенту, который его не прочтёт. Сжимает — если
клиент принимает gzip (RFC 9110, §12.5.3): своё имя (`gzip`, `x-gzip`)
важнее `*`, вес `q=0` — отказ, вес не числом — тоже. Сжатое тело
получает `content-encoding: gzip`, а прежний `content-length` снимается.
Ответ обработчика слой копирует, а не правит на месте: одну и ту же
таблицу ответа обработчик вправе отдавать на каждый запрос, и сжатое
для одного клиента не уезжает следующему.

```lua
local r = router.new({ entry = { compress.layer() } })

r.get('/nodes', function()
    return router.json({ nodes = nodes })
end)

local answer = r.dispatch({ method = 'GET', path = '/nodes', headers = { ['accept-encoding'] = 'gzip, br' } })
answer.headers['content-encoding']                 --> gzip
answer.headers.vary                                --> Accept-Encoding
compress.inflate(answer.body)                      --> {"nodes":[…]}
```

**Метку клиенту с gzip слой помечает слабой.** Сжатое тело — другое
представление (RFC 9110, §8.8.1), и сильная метка, общая у двух видов,
обещала бы одни и те же байты там, где их нет: кэш, собирающий ответ
из кусков (`Range`), смешал бы байты gzip с несжатыми. Поэтому сильная
метка `"…"` клиенту, принимающему gzip, уходит как `W/"…"`; уже слабая
второй пометки не получает, а значение без кавычек — не метка вовсе,
и слой его не трогает. Клиенту без gzip метка остаётся сильной.

Правило метки и `vary` одно для 200, 304 и ответа на `HEAD`, и длина тела
в нём не участвует: у 304 и `HEAD` тела нет, и по ним не решить, сжал
бы слой ответ или нет. Короткий ответ клиенту с gzip уходит
несжатым, но со слабой меткой — RFC этого не запрещает, зато 200 и 304
на один запрос несут одну и ту же метку и один `vary`: 304 обязан нести
`vary` ответа 200 (RFC 9110, §15.4.5), а по метке кэш сопоставляет 304
со своей копией (RFC 9111, §4.3.4).

Слабую метку браузер присылает назад как есть, а раздача файлов и слой
`etag` роутера сверяют `if-none-match` по правилу RFC — пометку `W/`
снимают, — и 304 приходит так же, как по сильной (документ
[tnt-router](https://github.com/tnt-skein/tnt-router), «Метка версии,
время правки и 304»):

```lua
local r = router.new({ entry = { compress.layer() } })

r.get('/panel/*path', router.files({ bundle = { ['app.js'] = string.rep('const a = 1;\n', 200) } }))

local gzip = { ['accept-encoding'] = 'gzip' }
local first = r.dispatch({ method = 'GET', path = '/panel/app.js', headers = gzip })
first.headers.etag                                 --> W/"0aa34f26"
first.headers.vary                                 --> Accept-Encoding

gzip['if-none-match'] = first.headers.etag
local again = r.dispatch({ method = 'GET', path = '/panel/app.js', headers = gzip })
again.status                                       --> 304
again.headers.etag                                 --> W/"0aa34f26"
again.headers.vary                                 --> Accept-Encoding

r.dispatch({ method = 'GET', path = '/panel/app.js' }).headers.etag   --> "0aa34f26"
```

**Поток остаётся потоком.** Кусок сжимается со сбросом и уходит клиенту
сразу: медленный клиент по-прежнему тормозит источник, а не копит память
узла. Пустой выход не отдаётся — пустой кусок сервер отправил бы концом
тела. Отказ источника посреди рвёт соединение без завершающего куска, как
и без слоя (документ [tnt-router](https://github.com/tnt-skein/tnt-router),
«Ответ по кускам»).

Проверено на настоящем `http.server`: libcurl через `http.client`
с `accept_encoding = 'gzip'` разжимает и строку, и поток
(`Transfer-Encoding: chunked` поверх `Content-Encoding: gzip`), а без
просьбы получает тело как есть.

Сжимается только gzip. HTTP `deflate` — это обёртка zlib, но старые
браузеры читали его голым DEFLATE, и выигрыша против gzip он не даёт;
brotli и zstd в системе не найти так же верно, как zlib.

## Уступки

zlib — это счёт, а не ввод-вывод, и пула нитей под него у Tarantool нет:
сжатие идёт в потоке событий и держит узел. Замер на 3.8, 4,9 МБ строк
выгрузки журнала:

| Уровень | Сжатие | Разжатие | Доля |
|---|---|---|---|
| 1 | около 430–500 МБ/с | 580–1300 МБ/с | 15,7 % |
| 6 | около 170 МБ/с | 780–1500 МБ/с | 13,9 % |
| 9 | около 65 МБ/с | 730–980 МБ/с | 13,8 % |

(меньшее — Linux, zlib 1.2.11; большее — macOS, zlib 1.2.12.) Поэтому вход
уходит в zlib кусками по 64 КБ, выход собирается в буфер того же размера,
и **между вызовами zlib — уступка**: на шестом уровне это доли
миллисекунды работы подряд.

**Внутри транзакции уступки нет**: она оборвала бы транзакцию memtx.
Сжатие в транзакции идёт целиком и держит узел всё своё время — большое
сжимают до `box.begin`. До `box.cfg` транзакции не бывает, и работа
уступает.

## Отказ и бросок

| Что | Как |
|---|---|
| испорченное, оборванное, больше предела, отказ памяти при разжатии | пара `nil, err` |
| данные либо кусок не строкой, чужой ключ настроек, формат не из трёх, уровень не 0…9, предел не больше нуля | бросок |
| кусок после `finish`, второй `finish` | бросок |
| zlib не завела поток (нехватка памяти, чужая zlib) | бросок |
| на узле нет zlib | бросок при первом вызове; у слоя — при сборке |

Бросок показывает на строку вызывающего:

```lua
compress.deflate(42)
--> app.lua:3: данные — строка, а не число
compress.deflate('a', { level = 10 })
--> app.lua:4: настройки.level — число от 0 до 9, а не 10
compress.inflater({ format = 'deflate' })
--> app.lua:5: настройки.format — одно из «gzip», «zlib», «raw», а не «deflate»
```

Узел без zlib — поломка поставки, а не данные вызывающего, поэтому бросок.
Узнать заранее — `compress.available()`; слой спрашивает это сам при
сборке, и узел без библиотеки падает при настройке, а не на первом ответе.

## Проверки

Сжатие проверяется настоящей zlib. Выход сверяется байт в байт с оракулом —
одним вызовом `deflateInit2_` и `deflate` с названными в проверке
параметрами: уровень, окно, память, стратегия, режимы сброса. Вход
проверки — строки выгрузки журнала, на которых соседние значения каждого
параметра дают другой выход (сверено на zlib 1.2.11 и 1.2.12). Двойник
берётся там, где настоящая библиотека нужного случая не даст: узел без
zlib (`compress._set_source({ load = … })`), отказ памяти, счёт уступок
и транзакция (`{ yield = …, in_txn = … }`). Что внутри настоящей
транзакции работа не уступает и транзакция фиксируется, проверено
на временном узле, рядом — отрицательный контроль: та же работа
с уступкой транзакцию обрывает. Стык проверен в настоящем роутере,
в реестре `tnt-middleware`, с раздачей файлов (слабая метка и ответ 304
по ней) и на настоящем `http.server` с `http.client` — там же раздача
отвечает 304 на вторую загрузку со слабой меткой.

Проверки лежат в `test/` и идут на luatest. Покрытие строк — 100 %,
убитых мутантов — 100 %.

## Чем пришлось поступиться

- **Слабая метка не годится для `If-Match`.** Условную запись RFC 9110
  (§13.1.1) сверяет сильно, и слабая метка там не совпадает ни с чем:
  клиент с gzip, взявший метку под слоем и приславший её в `If-Match`,
  получит от обработчика, который держит RFC, отказ 412. Ответу чтения,
  метку которого клиент понесёт в условную запись, ставят
  `cache-control: no-transform` — метка остаётся сильной, а тело уходит
  несжатым. Обработчик, сверяющий `if-none-match` сам, берёт сверку
  роутера, а не равенство строк: метку клиент с gzip присылает
  с пометкой `W/` (документ [tnt-router](https://github.com/tnt-skein/tnt-router),
  «Чем пришлось поступиться»).
- **На `HEAD` слой не сжимает**: роутер отвечает на него телом
  без содержимого, и сжимать нечего. Метка и `vary` у `HEAD` те же, что
  у `GET`, — их правило длины тела не спрашивает, — а длиной заголовки
  расходятся: у `HEAD` стоит `content-length` несжатого ответа — его
  называет роутер, который длину знает, — а у `GET` вместо неё
  `content-encoding: gzip` и длина сжатого, которую ставит сервер.
- **Имена заголовков — в нижнем регистре**, как держит договор роутера.
  Ответ, собранный руками с `Content-Encoding` в другом регистре, слой
  не узнает и может сжать второй раз.
- **Тело запроса слой не разжимает.** `Content-Encoding` у запроса роутер
  не знает; кому нужно — `compress.inflate` в обработчике с пределом.
- **Байты сжатого зависят от zlib узла.** zlib-ng (системная zlib Fedora
  с 40-й) сжимает иначе, хотя разжимает то же самое. Сжатое не сравнивают
  между узлами и не считают по нему свёрток — только по исходному.
- **Нулевой уровень режется на блоки по кускам входа**: его выход
  зависит от того, как вход подавали, и с одним вызовом zlib байт в байт
  не сходится. Разжимается он одинаково.
- **Предел потока — на весь поток, а не на кусок.** Кусок в 64 КБ
  способен разжаться в 64 МБ, и поток с пределом «бесконечность» получит
  их одним `write`: такой предел ставят только тем кускам, чей размер
  держат сами.
- **Сжатие в транзакции держит узел** — см. «Уступки».
- **Сжатый ответ выдаёт тайну длиной (BREACH).** Если в одном теле
  лежат тайна (ключ, токен) и то, что прислал клиент, по длине сжатого
  ответа тайну подбирают побуквенно — и TLS от этого не спасает. Слой
  этого не знает и не проверяет: маршруты с такими ответами держат
  в группе без слоя (фильтр `{ 'compress', path = '/api' }` ставит его
  только туда, куда назван), а ответу, который сжимать нельзя, ставят
  `cache-control: no-transform`.
